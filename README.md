# 通用业务管理平台后端模板

这个目录供业务负责人和研发共同定义新平台。现阶段可以运行检索验收工具。HTTP 服务、表结构和审批执行器由派生项目按需求实现。

## 业务人员从这里开始

1. 复制本模板，在[项目说明](description/project.md)中填写平台名称、负责人和记录范围。用一句话写清谁遇到了什么问题。
2. 拿一条虚构记录走一遍流程。例如，经办人提交设备验收单，负责人决定是否通过，经办人查看结果。写下每一步谁能看、谁能改、遇到退回怎么办。
3. 复制[能力样板](description/capability/application/template.md)，把上述例子写成可以核对的结果。让经办人确认重复点提交、无权查看和服务重启时应看到什么。
4. 研发在隔离环境通过正式入口跑通这些例子，回填观察结果。业务负责人核对页面或导出结果后在能力文档记录日期和结论。

## 研发入口

先读 [AGENTS.md](AGENTS.md)。Python 3.10+ 且带 SQLite FTS5 时，在本目录运行 `python3 tools/check_search.py` 即可验证关键词命中与排序。可选驱动、中文分词策略和向量检索步骤见[存储与检索](description/architecture/data/search.md)。独立 MySQL 验收与容器配置见[部署说明](../README.md)。

## 可以复制给开发助手的第一段话

> 请基于这个模板为设备验收小组梳理首个场景。经办人提交设备编号和验收说明，负责人可以通过或退回，经办人只能查看本人记录。用虚构设备 EQ-001 举例：资料完整时负责人可以通过，缺少说明时提示补充，两次点击提交只产生一条待审记录。首轮只覆盖提交、审批和结果查询，先读 description/project.md，把角色、状态和验收例写入能力文档，列出需要我确认的规则。请等我确认后，再在派生项目中实现这一条流程。

将设备、角色、示例和预期换成自己的业务用语即可。
