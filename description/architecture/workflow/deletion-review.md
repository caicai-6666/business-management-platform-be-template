# 可选的删除审核

仅在业务要求审批删除时采用。申请人提交原因；服务端验证权限，冻结资源 ID、实例版本、跨平台通行证、申请人身份及归属文件引用。正式资源在审核期间继续按原权限访问。同一实例最多一条活动申请，使用事务和唯一约束阻止并发重复申请。

| 阶段 | 持久化与恢复 |
| --- | --- |
| 发送申请 | 保存申请 ID 并原子领取投递任务。明确未发送可退避重试；已受理保存发布 message_id；超时或响应丢失进入送达未知，先对账。登记中心的去重只覆盖其未确认窗口，重启后避免盲目重发。 |
| 接收决定 | 验证可信来源，反馈的 request_id 匹配申请发布的 message_id。用反馈自身的 message_id 作消费幂等键和 ack 标识，记录审核者、决定、时间。未知关联或冲突保留现场，暂缓 ack。 |
| 拒绝 | 持久化拒绝结果，恢复可申请状态后 ack。保留正式文件、索引和记录。 |
| 批准 | 持久化批准结果与待执行任务。执行前核验冻结实例及版本，防止同名替换或新版本被误删。按归属清理文件、全文与向量索引，最后清理权威元数据。全部完成并保存成功回执后 ack。 |
| 中断与重放 | 记录已完成步骤、尝试次数及下次执行时间。重启后重新领取过期任务，逐步核验实际结果。历史反馈重放时用持久化回执核实一致后补 ack。 |

对用户分别展示投递、审核和执行状态。已批准但清理失败时显示待恢复步骤。验收至少覆盖拒绝后仍可读、版本不符、部分清理中断、重复反馈和成功回执后 ack 丢失。业务负责人确定回执保留期与人工对账责任人。
